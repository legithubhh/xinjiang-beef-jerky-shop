## 📝 使用指南

### 新开发者入门

1. **首先阅读** `CHARTER.md` - 了解项目基本原则
2. **然后阅读** `DEVELOPMENT.md` - 学习开发流程
3. **严格遵守** `SECURITY.md` - 安全规范必须执行
4. **参考** `ARCHITECTURE.md` - 理解系统设计
5. **查看** `LOGS/` - 了解近期开发动态

### 日常开发

- **开始工作前**: 查看 `LOGS/` 了解最新进展
- **开发新功能**: 更新 `API.md` 和 `ARCHITECTURE.md`
- **完成任务后**: 在 `LOGS/YYYY-MM-DD.md` 记录
- **发布版本**: 更新 `CHANGELOG.md`

### 文档更新规范

```markdown
# 文档头部必须包含

> 📄 文档说明
> 
> **版本**: x.x.x
> **最后更新**: YYYY-MM-DD
> **作者**: 姓名

# 变更处必须标注
```

## 📌 重要提醒

### 文档维护责任

- **人类开发者**: 审查和批准重要文档变更
- **AI 协作者**: 编写和更新文档草稿
- **共同责任**: 保持文档与实际代码同步

### 文档质量标准

- ✅ 准确 - 与实际实现一致
- ✅ 完整 - 覆盖所有重要方面
- ✅ 清晰 - 易于理解和执行
- ✅ 及时 - 变更时立即更新

### 禁止行为

- ❌ 代码已改但文档未改
- ❌ 绕过文档直接开发
- ❌ 删除历史日志
- ❌ 修改他人日志内容
